How I Work

Process

I don't start by picking tools. I start with which decision you want to make faster.

Diagnose

Which question currently takes longest to answer, and why that answer matters.

Design

Where data comes from and where it goes — agreed in writing, with cost and timeline, before any build.

Build

Start small at the most painful point. A perfect system nobody uses isn't worth building.

Hand over

Documented so your team can run it. If it only works while I'm there, it failed.

Ways to work together

I hold a full-time role, so I don't take on several engagements at once — one of the three below, within what I can genuinely deliver.

① Diagnostic session

Where your data stands and what to fix first, written up as a document you can act on even if you never hire me for the build.

~1 week · calls + written diagnostic

② Dashboard build

From metric definitions through to automated refresh — Power BI or web, whichever fits.

~2–4 weeks · metric dictionary + dashboard + handover

③ Pipeline pilot

A small version that consolidates data and connects AI analysis and Q&A, so you can see the effect before committing further.

~6–8 weeks · scoped to one painful area

Timelines and cost depend on the state and scope of your data, so they're agreed after an initial conversation. If a timeline isn't one I can honour, I'll say so and help you find another route.

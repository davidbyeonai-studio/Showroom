매달 숫자를 다시 뽑는
일을 없애기

보고서를 만드는 데 쓰던 시간을 보고서를 읽는 시간으로 되돌려주는, 스스로 갱신되는 Power BI 대시보드 설계.

역할요구 정의 · 데이터 모델링 · 시각화
대상경영진 · 영업 · 운영 담당
스택Power BI · DAX · SQL · Google Sheets
형태자동 갱신 · 모바일 대응
공개 버전 안내. 아래 화면과 수치는 모두 더미 데이터이며, 회사 브랜딩과 실제 실적은 제거했습니다. 구조·설계 방식만 공개합니다.

1. 문제 — 리포트가 아니라 리포트 만드는 일이 업무가 된다

많은 조직에서 "이번 달 실적 정리"는 사람이 매달 반복하는 수작업입니다. 원본 시트에서 필터를 걸고, 복사해 붙이고, 피벗을 다시 만들고, 지난달 파일과 비교합니다. 담당자가 휴가라도 가면 보고가 멈춥니다.

더 큰 문제는 그렇게 만든 숫자가 매번 조금씩 다르다는 점입니다. 누가 언제 뽑았는지에 따라 기준이 달라지고, 회의에서 두 부서의 숫자가 어긋나면 논의는 내용이 아니라 숫자 검증으로 흘러갑니다.

2. 접근 — 시각화보다 정의가 먼저

대시보드를 예쁘게 만드는 일은 마지막 단계입니다. 실제로 시간이 가장 많이 드는 건 지표의 정의를 하나로 못 박는 일입니다.

  • 지표 사전 작성 — "매출"이 무엇을 포함하고 무엇을 제외하는지, 어느 날짜 기준인지 문서로 확정
  • 데이터 모델 설계 — 원본 시트를 그대로 붙이지 않고, 팩트/차원 구조로 재구성
  • 자동 갱신 파이프라인 — 원본이 바뀌면 사람 손을 거치지 않고 반영되는 경로 구성
  • 읽는 사람 기준 레이아웃 — 경영진용 한 장, 실무자용 상세 뷰를 분리

3. 자주 놓치는 지점

  • "모든 걸 다 보여주는" 대시보드는 아무도 안 본다 — 첫 화면은 질문 3~5개로 제한합니다.
  • 필터 기본값이 곧 메시지다 — 열자마자 보이는 상태가 그 조직의 기본 시각이 됩니다.
  • 예외 처리 규칙을 눈에 보이게 — 취소·보류·반품을 어떻게 셌는지 화면 안에 적어둡니다.
  • 모바일에서 열린다 — 경영진은 대부분 회의 중 휴대폰으로 확인합니다.

4. 결과

매달 반복되던 취합 작업이 사라지고, 회의에서 숫자의 출처를 다투는 일이 줄었습니다. 같은 화면을 함께 보며 시작하니 논의가 "이 숫자 맞아요?"가 아니라 "그래서 뭘 할까요?"에서 출발합니다.

소매 현장에서는 수천 개 품목의 일일 원가·매출 리포트를 자동화해, 아침에 열어보면 전날 상황이 이미 정리되어 있는 구조를 만들기도 했습니다. 규모는 달라도 원리는 같습니다 — 사람이 반복하는 계산은 사람이 하지 않는다.

5. 이런 경우에 도움이 됩니다

  • 엑셀로 매달 같은 리포트를 만들고 있는 경우
  • 부서마다 다른 숫자를 들고 회의에 들어오는 경우
  • BI 도구는 샀는데 실제로는 아무도 열어보지 않는 경우
  • 지표 정의부터 다시 정리해야 하는 경우
